# Crawler Codebase Map

This is a Go/raylib dungeon crawler prototype. The runtime package is `internal/app`, with `main.go` only calling `app.Run()`.

## Commands

- Test: `go test ./...`
- Build: `go build -o .\.codex-build\crawler-3d.exe .`
- Run from source: `go run .` — **opens a real game window; never use it as a smoke test (see below). Prefer the `run` skill.**
- The project currently relies on `raylib.dll` being available beside the executable or in the working directory.

This workspace is Windows-first. Prefer bash if it is installed, but do not block on it; PowerShell is the default shell here.

### Smoke-checking changes — DO NOT `go run`

**`go run .` actually opens the game window on the user's screen.** It is not a headless smoke test. Running it during the user's working hours pops a real window over whatever they're doing and is genuinely disruptive.

For verifying that a change builds and links cleanly:

- Use `go build ./...` (or the named build above) — that exercises compile + link without launching anything.
- Run `go test -count=1 ./...` and `go vet ./...` for correctness.
- For UI / rendering changes, REPORT the change and let the user open the binary themselves. Do not "just check it boots." Describe what should be visible and stop.

Only run the game when the user has explicitly asked you to (e.g. "launch it", "run it", "show me"). Even then, prefer the `run` skill which goes through the project-aware launcher.

## Input — gamepad-first (binding)

This is a **gamepad-first game.** The controller is the primary, designed-for input device; keyboard and mouse are secondary conveniences layered on top — never the only way to do anything. Treat the following as contracts, not preferences:

- **Every UI surface — title, menus, HUD, combat, overlays, modals, the panels tabs — MUST be fully operable with a controller alone.** No action, tab, slot, toggle, target, or item may be reachable only by mouse or only by a keyboard key with no pad binding. When you add a surface, design the controller flow FIRST (D-pad/stick to navigate, A confirm, B back), then layer keyboard/mouse on top.
- **All input reads route through the semantic `input` package** (`ConfirmPressed`, `BackPressed`, `CursorUpDown` / `CursorLeftRightWrap`, `MenuTabPrev/NextPressed`, `PanelsTogglePressed`, `LookStick`, …). Do NOT call `rl.IsKeyPressed` / `rl.IsGamepadButton*` / `rl.GetMouse*` at a battle/explore/render call site — add or extend a predicate in `input/input.go` so each binding lives in one remappable place. (Exception: render may read the live pointer position at DRAW time for purely visual hover cues — non-remappable visuals, not input bindings. Actual click routing goes through the `input` package and render-cached hit rects, e.g. the Equipment tab's `EquipPanelSlotHit` / `EquipPanelPickerRowHit`.)
- **No obtuse button combos.** Use the established vocabulary; don't invent ad-hoc chords:
  - A / Cross = confirm · B / Circle = back / cancel
  - Y / Triangle = open panels (Tome) · Start / Options = pause · Select / Share = quit / debug-flee
  - L1/L2 + R1/R2 = page tabs / cycle prev-next target · D-pad + left stick = navigate · right stick = free-look
  - Square / X and L3 / R3 are intentionally unbound — claim one of those before reaching for a combo.
- **On-screen hints read controller-first** (or device-neutral). Don't write a prompt that assumes a keyboard ("Press Z…") without the pad equivalent.

Older files without `ceiling:` / `elevation:` parse fine and get blank ceiling / ground elevation layers.
- `internal/app/core/party.go`: party class definitions, skill registry (now with `SkillTag` for Phys/Magic/Heal/Buff, `PlayerCastable` flag separating menu-eligible skills from enemy-only ones, and `SkillEffect.AppliesIngest` carrying the mantrap's swallow status), damage / heal / burn / sleep-duration formulas, skill affordability (`CanAffordSkill` wraps `SkillCost`), the mitigation helpers (`ApplyArmor` for phys + `ApplyMagicDefense` for magic with `MagicDefense(stats)` deriving from WIS), dodge / crit / status-resist primitives (`DodgeChance` + `RollDodge`, `CritChance` + `RollCrit`, `ShortenStatusDuration`), `XPForLevel` / `AddXP` / `SpendStatPoint` / `FirstPendingLevelUp` for the leveling system, the table-driven `statTable` powering `StatLabel`/`StatValue`/`StatPreviewLine` (modal before→after deltas), and `PlayerCastableSkills` (used by battle's init to assert handler coverage).

Combat reads through ALL THREE Effective\* readers: armor + mdef flow into mitigation (`damagePartyMember`), and stat bonuses flow into `SkillDamageFor` / `SkillHealFor` (skill scaling), `applyAttack` (basic-attack damage + accuracy), `applySteal` (steal chance + STR cut), `RollDodge` / `RollCrit` reads, `actorSpeed` (turn order), and `ShortenStatusDuration` callers (status-resist via WIS). Base `m.Stats` stays clean — level-up spends edit the base, equipment re-renders the sheet at read time.
- `internal/app/core/selectors.go`: read-only party/battle selectors, turn forecast generation, wrap-aware living-member walk, `PackXPValue` and `AwardBattleXP`, plus the "available" variants (`PartyMemberAvailable`, `ActivePartyCount`, `WrapNextAvailablePartyMember`, `AvailablePartyTargets`, `FirstAvailablePartyMember`) that exclude ingested members and `MantrapHasPrey` / `ReleaseIngestedBy` / `ReleaseAllIngested` for the Ingest status lifecycle.
- `internal/app/core/economy.go`: gold + loot economy. `ItemDrop` (per-defeat item table), `AwardBattleLoot` (rolls each pack member's `GoldMin..GoldMax` + `Drops`, adds to `g.Gold` / `g.Inventory`, called from `winBattle` after `AwardBattleXP`), the shop catalog/sell helpers for a future merchant/tile entry point (`ShopCatalog` = priced registry items, `SellableStacks`, `ShopSellPrice` = half-price floored at 1), and the `ShopTab` (Buy/Sell) enum. Item prices live on `ItemDefinition.Price`; per-enemy gold/drops/`Flying` on `EnemyDefinition`.

- `internal/app/core/save.go`: JSON save/load. `SaveData` is the persistent subset (map id, player tile/facing, party, inventory, gold, quests, step count); `SaveGame` writes `saves/save.json` (cwd/exe-relative via `ResolveAssetDir`), `LoadSave` reads + version-gates it, `GameStateFromSave` rebuilds the area FRESH then overlays the saved progression (save-POINT semantics — packs/chests/fog reset, same as an area transition). Title-screen Continue + Options→Save Game are the entry points.
- `internal/app/core/condition.go`: enemy wound-state thresholds and labels.
- `internal/app/core/enemies.go`: enemy kind enum (13 kinds today: Rat, Bat, DiseasedRat, Goblin, GoblinMage, Amoeba, VenusMantrap, CaveSpider, VampireBat, Wisp, StoneGolem, Necromancer, Skeleton — the const block is the source of truth), per-kind definitions (full `Stats` block — STR/DEX/INT/WIS/VIT/SPD, symmetric with the party side; the legacy standalone `Speed` field was retired), `Armor` + `MDef` mitigation, `XPValue`, `Skills` + `SkillCastChance` + `SpellPower` + `LifestealPercent`, and lookup helpers.
- `internal/app/core/enemyvisual.go`: raylib-free enemy visual override persistence. `SpritesDirName` is the single source for the authored sprite / `visuals.json` asset folder (`maps/sprites`), `EnemyVisualsPath` resolves `visuals.json`, and `LoadEnemyVisualOverrides` / `SaveEnemyVisualOverride(s)` read/write per-slug `EnemyVisualOverride` values.
- `internal/app/core/items.go`: item + equipment registry. Consumables (crust of bread, cheese, jerky — `Slot == SlotNone`, `HealAmount` heals) and equipment items (sword, shield, cap, ring, amulet) live in one `itemDefinitions` slice. **New `ItemKind`s are APPENDED at the end of the enum** — `ItemKind` serializes as its int value in saves (`SaveData.Inventory`), so a mid-enum insert renumbers later items and corrupts saves; the registry/display order is the slice order (independent of enum value). Equipment items carry `Slot` (`SlotHand` / `SlotArmor` / `SlotAccessory`), plus per-slot `ArmorBonus` / `MDefBonus` / `StatBonus`. `EquipSlotIndex` enumerates the five concrete equip slots; `SlotIndexLabel`/`SlotIndexType` read the init-asserted `equipSlotInfo` table. Inventory add/consume/empty helpers, kind-by-name lookup.
- `internal/app/core/timing.go`: timed-hit minigame state machine (press / charge / sequence / multi-press tally), grade dispatch, damage/heal/defense scaling. `NewMultiPressState(rng, duration, count)` builds tally-mode bars: N accept windows + a late commit zone, each press in an unconsumed window scores a hit, commit-zone press or timeout resolves with the tally. Single-window bars stay on `NewTimingState`.
- `internal/app/core/vfx.go`: VFX intent layer — battle/explore code pushes `VFXRequest` values onto `g.VFXQueue` (via `EnqueueEnemyVFX` / `EnqueuePartyVFX` / `EnqueueTileVFX`), the render layer drains them each frame and materialises particles. Avoids battle → render imports. `RequestVFXReset` / `TakeVFXResetRequest` is the pool-clear signal pair (battle exit, area transition, return-to-title).

- `internal/app/input/`: shared key semantics for confirm/back/menu/targeting/exploration controls, panel tab-paging (`MenuTabPrev/NextPressed` — L1/L2/R1/R2 + Tab/Shift+Tab) and horizontal cursor wrap (`CursorLeftRightWrap`); analog-stick edge detection plus the analog right-stick `LookStick` reader for free-look.

Per-skill VFX queued via `core.EnqueueEnemyVFX` / `core.EnqueuePartyVFX`; multi-hit Swipe scales damage passes by `multiPressPasses` (reads the tally bar's `Hits` count).

The `barEnemyHP` token is retained for that future reveal skill.

- `internal/app/render/weather.go`: `DrawWeather` — the ambient-rain screen-space overlay (bluegray darkening wash + stateless animated streaks driven by `rl.GetTime()` and `weatherHash01`, with per-streak varied thickness). The `rainVisuals[core.RainKind]` table sets each kind's peak wash alpha / streak count / streak alpha, scaled by `Weather.Intensity`; a final bright near-white blank paints `Weather.Flash` for heavy-storm lightning. Drawn after the 3D pass but below the HUD so combat text / menus stay readable through the storm.
- `internal/app/render/lighting.go`: lighting shader load / uniforms / per-area profiles, plus the billboard fog shader (`billboardFogFragmentShader`). BOTH fragment shaders alpha-test-discard transparent fragments so they don't write depth — without it, a quad's transparent pixels stamp depth holes that clip whatever's drawn behind them. The world shader uses `if (texel.a * colDiffuse.a < 0.5) discard;` (hard foliage cutouts: trees behind trees vanishing). The **billboard** shader uses a much lower `if (texel.a < 0.08) discard;` — high enough to kill the transparent quad corners (which otherwise clip the particles drawn last in the 3D pass — the "sprites cut up by an invisible bounding box" bug), low enough to keep soft alpha-blended sprite edges that 0.5 would harden. The `fogCeiling` constant in `distancefog.go` is the single source for the fog clamp ceiling: both fragment shaders carry a `{{FOG_CEILING}}` token in their `clamp(fog, 0.0, {{FOG_CEILING}})`, and `resolveShaderFogCeiling` substitutes the Go constant in at `LoadShaderFromMemory` time — so there's no hand-sync, just edit `fogCeiling`.
- `internal/app/render/distancefog.go`: owns the per-frame lighting-profile cache (`cacheLightingProfile` / `resolvedLightingProfile`) that DrawWorld populates and the billboard draws read. The actual billboard fog wash runs through the `billboardFogShader` shader pair in `lighting.go` — multiplicative tint can't lerp toward fog color, so each of the three billboard draws (drawFieldPacks / drawBattlePack / DrawPartySprites) wraps its loop in `BeginShaderMode(assets.billboardFog.shader)`. The shader uses the same `1 - exp(-density · dist)` curve and `fogCeiling` clamp as the world fog shader, so billboards recede in lockstep with the lit geometry around them.
- `internal/app/render/vfx.go`: particle pool + `TickAndDrawVFX` (drains `g.VFXQueue` → seeds per-kind spawn patterns → ticks → draws). 14 spawn patterns covering melee impact, ember, heal, smite pillar, frost shards, venom mist, arc flashes, steal pop, death dust, stoneslam ground burst, sleep/web/confuse/ingest status FX. Bounded by `particleHardCap = 2048`; `ResetParticles` is called from battle exit + area transition + return-to-title via the `core.VFXResetRequested` flag pair.
- `internal/app/render/timing.go`: timed-hit bar rendering (press / charge / sequence / multi-press tally bars, flash hold, quality popup). `qualityVisuals` is the per-grade color + throb-intensity table. `drawTallyBar` paints N accept windows + a late commit zone for multi-press skills.
- `internal/app/render/resources.go`: procedural resource loading, area material models, font loading. `loadEnemyVisuals` builds the per-kind `enemyVisual` table (size / yOffset / depthOffset / shadowRadius / shadowOffsetX,Z / markerY,X / tint) as CODE DEFAULTS, then overlays author overrides from `maps/sprites/visuals.json` (`core.LoadEnemyVisualOverrides`, keyed by `core.EnemySlug`) on top — missing/malformed file ⇒ defaults stand. Authored PNGs load from `core.SpritesDirName`; door-prop coverage is guarded by `assertDoorProps` alongside `assertDecorCoverage` / `assertPropCoverage`. The Feral Rat PNG filename derives from `core.EnemySlug(EnemyRat)` (= `feral_rat`), so its display Name and asset name can't drift (pinned by a core test).
- `internal/app/render/foepreview.go`: the editor Foe Visualizer's live preview. `DrawFoePreview(rect, assets, kind, override)` renders one foe's billboard + contact shadow + target chevron into a panel via a cached off-screen `RenderTexture2D` (raylib has no sub-rect 3D viewport), using the EXACT ordering `drawBattlePack` does so the preview is faithful. `LiveFoeOverride` reads the currently-loaded visual back as a `core.EnemyVisualOverride`; `CloseFoePreview` frees the cached texture on modal close. Contact-shadow XZ is welded to the sprite's final footprint via `shadowFootprint` (world.go) — moving the sprite always moves the shadow; `shadowOffsetX/Z` are an explicit extra nudge, not a separate anchor.
- `internal/app/render/theme.go`: HUD color tokens, rounded panel helpers, shared text shadows, `drawArrowMarker` / `drawTextWithShadow` helpers.
- `internal/app/render/theme_export.go`: theme accessor for non-render packages (editor, title).

## Gameplay Notes

- Movement is tile-based with short animation. `W/S` step, `A/D` strafe, `Q/E` or arrows turn. Walls and prop tiles (trees / boulders / large bushes) both block.
- Free-look: right-click drag (mouse) or the right analog stick (pad); both recenter smoothly on release. Mouse is per-delta (`MouseSense`); the stick is dt-scaled (`StickLookSense`).
- Ambient rain (atmosphere only, no gameplay effect): outdoors (open-sky areas per `core.AreaIsOutdoor`), each landed step off-cooldown rolls `RainStartChance` to begin a storm. A bluegray wash eases in and darkens the view, then rain falls for `RainMinSteps`..`RainMaxSteps` (short — ~0.7–2 phases of the 150-step day cycle), then lifts; a `RainCooldownMin`..`RainCooldownMax` clear spell follows before rain can roll again. Each storm is a weighted `RainKind` — light shower (faint, lightest filter), normal rain, or heavy storm (dense + darker, plus occasional lightning flashes via `LightningInterval*` / `LightningDecayPerSec`). Walking under a roof recedes any active storm. State carries across area transitions like the day/night phase. Tuning in `config.go` (durations / chances / lightning) and `render/weather.go`'s `rainVisuals` table (per-kind look).
- Pause menu ("small start"): `P`, `Esc` (only outside battle, so Esc keeps working as "back / cancel target" in combat), or gamepad Options/Start button (`GamepadButtonMiddleRight`). Three rows: **Options ▸**, **Debug ▸**, **Quit**. (The Shop row was removed — the shop overlay code in `explore/shop.go` / `render/shop.go` is intact but currently has no entry point; wire `openShop` to a merchant / tile when one exists.) Options ▸ opens a submenu (Display fullscreen/windowed toggle, Party Stats → Tome, Restart, Close). Debug ▸ always opens its submenu (no longer gated behind "debug mode on") — first row is the **Debug Mode: On/Off** master toggle, followed by Enemies / Advance Time / Easy Battle Quit / Render Log toggles and the **audio sound-tester** (jukebox, moved here from the top level), then Close. Both submenus: Up/Down navigate, Confirm activates, Back returns to explore.
- Game panels overlay ("big start"): keyboard `I` or gamepad middle button (`GamepadButtonMiddle` — PS button on DualSense, guide button on Xbox, closest raylib exposes to the PS5 touchpad click). Out-of-battle only. Six tabs (Character / Equipment / Items / Skills / Quests / Map) page with L1/L2/R1/R2 (pad) or Tab/Shift+Tab (keyboard); per-tab keyboard shortcuts are C/E/I/K/**J** (Quests — Journal, since Q is turn-left)/M. The d-pad/stick drives the in-tab cursor — Left/Right selects the party-member column, Up/Down moves the slot row or zooms the Map. A persistent info strip below the tab strip shows the current **area name** (left) + party **gold** (right) on every tab. Pressing the same button again — or Esc / B / Circle — closes the overlay. Equipment tab works like the Items menu: walk members × slots with the d-pad and Confirm (or click) a slot to open its picker — a smaller sub-modal listing the items eligible for that slot plus an Unequip row; Confirm/click a row to equip (swapping the displaced item back to inventory) or unequip, Back / click-outside closes the picker. Skills tab is a per-member summary of the three Diablo-2-style skill trees (tree name + invested/total ranks + theme); Confirm opens the tree modal (`render.DrawSkillTreeModal`) where `SkillPoints` are spent into per-node ranks (`PartyMember.TreeRanks`, keyed by node ID; data in `core/skilltrees.go`). **UI only for now** — investing fills pips + gates prerequisites but grants NO combat effect yet (the legacy per-skill tier ladder in `core/skilltree.go` is currently inert; effect-wiring is a later pass). Out-of-battle use: on the **Items** tab Confirm (or **Use** = F / □) uses the cursored healing consumable; on the **Skills** tab **Use** (F / □, kept off Confirm which now opens the tree modal) casts an out-of-battle Heal-tag skill: `core.OutOfBattleHeals(member)` gathers them, and one heal casts directly while several (the Cleric's Prayer + Mass Mend) pop a heal chooser (`HealPick*`, `drawHealPicker`) first. Single-target heals (Prayer) then route through the shared ally-target picker (`UseTarget*`, living members only); party-wide Mass Mend applies to everyone at once. Skills bill the caster's MP; items consume one stack. See `explore/panels_use.go`. Map tab honors `g.Visited` for fog-of-war: unrevealed tiles paint flat fog (same fill as out-of-bounds — the layout doesn't leak through); every successful step marks the 3×3 reveal radius around the destination. Pack/chest/door markers only show on revealed tiles.
- Battles start when the player is adjacent to a live enemy pack; if needed, the player rotates to face it first. The engaged pack IS the encounter — packs are authored on the map (PackSpawns) and there's no spatial clustering at runtime.
- Pack AI modes (authored per pack in the editor's pack-edit modal, A to cycle; runtime planners in `core/packai.go`): `PackAINone` (stationary default), `PackAIJunkyardDog` (wander leash / lazy chase), `PackAIPatrol` (paces the X axis ±`PatrolRadius` around home, bouncing at walls/ends via the runtime `Pack.PatrolDir`, engages only if it paces onto the player), `PackAISkittish` (flees when the player is within `SkittishFleeRadius`, else wanders; never engages). New modes are the standard PackAI five-site edit (enum + `PackAICount`, `packAIPlanners`, `packAINameTable`, `packAILabels`, `mapfile.PackAINames`); the editor + mapfile pick them up via `PackAICount` / `PackAILabel`.
- Economy: enemies pay out gold (`GoldMin..GoldMax` per member) + roll item `Drops` on defeat (`AwardBattleLoot` in `winBattle`); gold is a shared `g.Gold` pool, shown top-left during exploration and on every char-menu tab. The shop (`core.ShopCatalog` / `ShopSellPrice`, `explore/shop.go`, `render/shop.go`) is built and functional but currently has no menu entry point (removed from the pause menu) — `openShop` awaits a merchant / tile.
- Quest journal: the char menu's **Quests** tab (keyboard `J`, or Options→Quests, or page to it). Read-only list (Up/Down browse). The journal is **empty for now** — `StarterQuests()` returns nil and there are no auto-complete hooks; the system (`Quest`, `AddQuest`/`CompleteQuest`, save-persisted `g.Quests`) is wired and ready to seed real objectives later.
- Combat juice: a Great/Excellent timed press triggers a hit-stop freeze AND a camera screen-shake (`Battle.ShakeTimer`/`ShakePeak`/`ShakeDur`, armed via `core.TriggerCombatShake`, applied in `render.Camera` as `ShakePeak·(ShakeTimer/ShakeDur)`, decayed in `updateBattleEffects`; wall-clock oscillation so it's visible through the freeze). The base shake on a good press is deliberately SUBTLE (`CombatShakeFor` returns `CombatShake{Great,Excellent}{Peak,Dur}`); a bigger shake (`CombatShakeBigPeak`/`CombatShakeBigDur`) is armed only on crits (`rollSkillCrit`) and AoE casts (`applyAoEDamage`) and overrides the base via TriggerCombatShake's keep-the-stronger rule.
- Selector pyramids (enemy target / friendly target / enemy-attack target) draw on a depth-disabled "always on top" layer via `drawMarkerOnTop` (flush batch → DisableDepthTest+Mask → draw → flush → restore) so they never clip into billboards/geometry. The active party member's "you're up" cue is NOT in-world — the floating active-turn pyramid + additive class-tinted turn-glow were removed (they read as noise over the sprite); it now reads entirely from the party ribbon, where the active card lifts (`activeCardLift`) + brightens and the others dim (`surfaceDimScrim`), see `DrawPartyRibbon`.
- Save/load: title-screen **Continue** (shown only when `saves/save.json` exists) loads the most recent save; Options→**Save Game** writes it. A save is a save-POINT — the map rebuilds fresh on load (packs/chests/fog reset), only party progression + gold + quests + position persist. See `core/save.go`.
- Flying enemies (`EnemyDefinition.Flying` — Bat / Vampire Bat / Wisp): a basic **melee** swing at a flyer loses `FlyingMeleeAccuracyPenalty` off its hit chance unless the wielder's weapon is ranged (`CanReachFlying` / `WeaponIsRanged`). Scaffold for "bring a bow to fight bats" — applied post-clamp so even an Excellent press can whiff a flyer with melee; the whiff log reads "can't reach the airborne …". Skills aren't accuracy-gated, so they're unaffected. Battle reads `core.MemberAttackHitsTarget` (target-aware) instead of `MemberAttackHits` for the basic attack.
- Chests block movement onto their tile; press Confirm (Space/Enter/Z) while adjacent to open the loot modal. Take one item with Confirm, or land the cursor on "Take All" to drain the chest. Esc closes. Looted chests render with an open lid and ignore further interactions.
- Battle input:
  - Confirm: `Space`, `Enter`, or `Z`
  - Back: `Esc` or `X`
  - Target/menu movement: arrows, `W/S`, `A/D`, `Tab` where applicable
- Mixed initiative: `buildTurnQueue` runs a tick-based ATB simulation. Each alive actor accumulates readiness equal to their `Stats.SPD` per tick; whoever crosses `core.ATBReadyThreshold` (=100) first acts, then carries the overflow into the next tick. The queue is naturally interleaved by who hits the gate when — there's no rigid "round" of one slot per actor. **SPD drives turn RATE, not just order**: each actor's readiness gauge PERSISTS across rounds in `g.Battle.Readiness` (seeded by `buildTurnQueue`, written back via the `persist` arg; the forecast's projection uses the non-persisting `projectNextRoundQueue` so it doesn't consume the real next round's state). Because the surplus carries over, a faster actor's leftover accumulates into extra turns over time — a SPD 6 actor takes ~2× the turns of a SPD 3 actor over a fight, not merely going earlier. The sim still stops once every alive actor has acted at least once (the "round" boundary that downstream code — poison-on-ingested ticks, enemy-attack cursor reset — hangs housekeeping off); `Readiness` resets at battle `Start`. Both sides read `Stats.SPD` (enemy `EnemyDefinition.Speed` was retired in favor of full `Stats` symmetry). Burn ticks fire at the start of the burning actor's own turn; Poison ticks at the END of the poisoned actor's turn.
- Enemies now carry full `Stats` (STR/DEX/INT/WIS/VIT/SPD) and a sibling `MDef` field — same shapes as the party side. DEX drives enemy dodge against player basic attacks AND enemy crit on those attacks (DEX-only roll, no timing bonus since enemies don't press a bar). WIS shortens player-applied statuses (Burn/Poison/Stun) via `tryProcStatus`. MDef damps magic-tagged player skills via `ApplyMagicDefense` inside `damageEnemy`. Authored per-kind in `enemyDefinitions`; custom enemies expose Stats + MDef via the editor's customStatSpecs table and the mapfile schema's MDef column (the parser accepts the legacy 17-field width for back-compat).
- Attack accuracy: the shared curve is `accuracyFrom(stat, quality)` = `AccuracyBaseline 0.55 + AccuracyPerStat 0.04·stat + timing bonus`, clamped [0, 1]. The basic attack is **weapon-governed**: `core.MemberAttackHits`/`MemberAttackDamage` read the wielder's equipped `WeaponType` (`core/weapons.go`, `weaponSpecs` registry) and roll to-hit + scale damage off that weapon's accuracy stat — **STR** for heavy melee (sword/axe/spear/2h/halberd/greataxe/club/hammer) and **unarmed**, **DEX** for light/finesse (dagger/rapier) and ranged (sling/bow/pistol/throwing-knives). `WeaponIsRanged` is an informational seam (no ranged-only rule wired yet — dodge still applies to all basic attacks). `MeleeAccuracy`(STR)/`RangedAccuracy`(DEX) are the named stat-curve wrappers (used by previews/tests). Skills are NOT accuracy-gated — they pay MP and shouldn't be double-jeopardied. Excellent timing functionally guarantees the hit at any stat.
- Dodge (party-side, basic-attack only): `core.RollDodge(rng, stats)` rolls before damage math in `resolveEnemyAttacker`. DEX-driven (`DodgePerDEX = 0.02`, cap `DodgeCap = 0.30`) — on a successful dodge the swing is voided entirely (no damage, no poison proc, no lifesteal). Enemy *skills* (goblin mage casts, stoneslam, web) are NOT dodgeable.
- Crit: party side rolls `rollSkillCrit` per damaging player skill — base `CritBaseline 0.05` + `CritPerDEX 0.008` + `timingGrades.CritBonus` (cap `CritCap 0.6`), multiplies post-mitigation damage by `core.CritMultiplier = 2`, and appends " Critical!" via `appendCrit`. Backstab keeps its signature "Excellent timing = guaranteed crit" branch inside `rollSkillCrit`, and its T2 (`CritDoubleOnExcellent`) stacks an additional ×2 via the helper's `double` return. CrushingBlow T3's separate `CritDoubleOnExcellent` doubles damage on Excellent INDEPENDENTLY of the universal crit (both can stack to ×4). Enemy basic attacks roll the same `core.RollCrit` against the enemy's `Stats` with `TimingQualityMiss` quality (no timing-grade bonus, pure DEX-driven), producing a flat ~5–10% crit floor; enemy skills don't crit.
- Magic Defense: party reads `core.EffectiveMDef(member)` (WIS via `MagicDefense(stats)` + any equipped item's `MDefBonus`); enemies read `EnemyInfoFor(*enemy).MDef`. Both sides flow into `ApplyMagicDefense` inside the damage helpers — symmetric with `ApplyArmor` on the phys side, same `max(dmg - mdef, 1)` floor.
- Status-duration shortening: `core.ShortenStatusDuration(duration, wis)` shaves `wis / StatusShortenDivisor` (=3) turns off enemy-applied Sleep / Poison / Webbed / Confuse on a party member and player-applied Burn / Poison / Stun on enemies (floor 1). Wis-driven scaling lives in this helper alone — the historical `WIS / (WIS + WispConfuseResistDivisor)` apply-resist roll specific to Wisp Confuse was retired; the universal shortener handles it now.
- Timing-bar JUICE: graded flashes throb (height pulse, scaled by grade); Miss flashes shake horizontally. Cursor color-previews the live grade while inside the press window. Excellent flashes spawn an expanding shockwave ring. Charge ticks freshness-flash on crossing. Sequence arrows pulse on correct land. Hit-stop pauses the world for 100ms (Great) or 160ms (Excellent) between the bar flash and the action's apply step.
- Charge bars (Prayer, Firebolt) arm with a `ChargeTimingIntro` pre-arm pause (3s) during which the bar shows a "Press to start" prompt instead of "CHARGE!". A fresh edge press during the pause skips it; otherwise the bar auto-arms when the pause elapses. `Battle.ChargeNeedsRelease` gates the engage check so the same Enter the player used to confirm the target can't bleed into the bar's held-state read — they must release once first, then a fresh press engages. The gate clears the frame after `AttackTimingHeld()` goes false. Combat log narrows during the timing bar to dodge the bar's left edge ([drawCombatLogPanel in render/battle.go](internal/app/render/battle.go#L313)).
- "Targeting" indicators (in-world yellow chevron, enemy-roster row highlight, friendly-target pyramid) all gate on the same render-package predicates so they never drift: `targetingEnemy(g)` for both enemy indicators (`Phase == BattlePlayer && ActionMode == ActionEnemyTarget`), `targetingAlly(g)` (plus an explicit `Phase == BattlePlayer` at the call site) for the friendly marker. They drop the moment the timing bar arms, so the cursor only shows while the player is actually picking a target, not while they're pressing the bar.
- Tile-character reference for `.map` files lives in the top comment of `internal/app/core/mapfile/mapfile.go`. New tile types are added there + `internal/app/core/map.go`'s const blocks + the `tileLabelTable` in `map.go` (init asserts coverage) + the canonical list (`propTileCharList` / `decorTileCharList` / `floorTileCharList`) so the renderer's coverage asserts pass + the editor's brush palette in `internal/app/editor/editor.go` (`layerBrushes` — drives both palette UI and grid-cell colors via `tileColorByChar`) + the renderer (`r.specialFloors` for universal floors, `r.decorModels` for decor, `r.propModels` for props, or an inline case in `world.go`'s `drawWorld` / `drawDecor` for hand-tuned variants — both inline sets are dispatched via `inlineDecorHandlers` / `inlinePropHandlers` in `render/resources.go`).
- Floor layer: `FloorDeepWater` ('W') is the sole *blocking* floor — renders flat (camera can see across), but `BlockedAt` reports true so movement / pack snapping / chest placement / canPlaytest all refuse it. Shallow water ('~') is walkable. The lilypad decor ('y') is pure visual and pairs with water tiles for the swamp aesthetic.
- Per-grade balance tunables live in `internal/app/core/config.go`: the `timingGrades` table (label / atk mult / def mult / accuracy bonus / crit bonus per Miss..Excellent) is the single source of truth; render-side color + throb intensity live in `qualityVisuals` (render/timing.go); audio cue per grade lives in `gradeSounds` (battle/battle.go).
- Enemies: `rat`, `bat`, `diseased_rat` (tier-3 rat variant, 60% chance to inflict Poison on a landed bite; carries no loot), `goblin` (tier-3 grunt), `goblin_mage` (tier-4 caster — `SkillCastChance` controls its mixed Firebolt / Sleep loadout), `amoeba` (tier-3 tank with `Armor: 8` — phys whiffs to 1 dmg, magic shreds it), `venus_mantrap` (tier-4 plant lurker — slow, beefy bite + signature `SkillIngest` that pulls a party member out of combat until the mantrap dies, max one prey per mantrap, see Ingested below).
- Status effects (none stack onto an already-affected target): **Burn** (enemy-side — Wizard Firebolt + Arc Bolt T3; flat tick at start of turn, 2–3 turns), **Poison** (Diseased Rat bite + Thief Venom Strike; flat tick at END of turn, 3–5 turns), **Sleep** (goblin mage `SkillSleep`; 2–5 turns, skipped at turn start, any damage > 0 wakes), **Stun** (Crushing Blow / Frost Lance / Smite-T3 procs on Great+ timing; skips a turn, damage does NOT clear it), **Webbed** (Cave Spider `SkillWeb`; halves SPD and blocks Ingest), **Confused** (Will-o'-Wisp `SkillConfuse`; per-action random retarget), and **Ingested** (mantrap `SkillIngest` — removed from the turn queue and untargetable until the mantrap dies; one prey per mantrap; Poison survives the lockout, Sleep + Defending clear). If every living party member is ingested at once the battle counts as lost (`core.ActivePartyCount == 0`). On battle exit, `core.ClearPartyTransientStatuses` wipes the party-side combat-only statuses (Sleep / Stun / Webbed / Confused / Defending); only **dead** (HP ≤ 0) and **Poison** persist into exploration.
- Armor + MDef: per-actor mitigation outside `Stats` (not buyable / not a level-up spend). `core.ApplyArmor` clips phys-tagged damage to `max(dmg - armor, 1)`; `core.ApplyMagicDefense` does the same for magic-tagged damage against MDef. Heal / Buff / None tags bypass both. Party-side both reads route through `core.EffectiveArmor(m)` / `core.EffectiveMDef(m)` so equipped items' `ArmorBonus` / `MDefBonus` stack on top of base. Enemies carry both fields directly on `EnemyDefinition`. Skill tags live on `SkillDefinition.Tag` (`SkillTagPhys`/`Magic`/`Heal`/`Buff`/`None`).
- Equipment: per-member 5-slot inventory (`RightHand` / `LeftHand` / `Armor` / `Accessory1` / `Accessory2`) stored in `PartyMember.Equipped`. Items declare a `Slot` type + `ArmorBonus` / `MDefBonus` / `StatBonus` on their `ItemDefinition`; the Equipment panel's slot picker moves items between the slots and the shared `g.Inventory`. `core.EquipItem` / `UnequipItem` are the low-level move primitives; `core.EquipFromInventory` / `UnequipToInventory` wrap them with the inventory consume/return math the picker calls. `EffectiveArmor` / `EffectiveMDef` / `EffectiveStats` fold bonuses on top of base values at read time, and combat reads through ALL three so every kind of bonus (armor / mdef / per-stat) lands on damage / heal / accuracy / dodge / crit / turn-order / status-resist.
- Render diagnostics log: pause-menu Debug submenu → `Render Log: On` toggles a per-frame snapshot writer (`crawler-render.log` under `%LocalAppData%\crawler\`). Init banner stamps shader compile + uniform locs + resource table counts; per-frame line carries camera pose, tile iter / cull / draw counts (walls / floor / ceiling / decor / props), torch count, lighting profile, shader IDs, battle flag. Throttled to ~10 lines/sec.
- Sky / depth-buffer note: `drawAdventureScene` in `run.go` MUST call `rl.ClearBackground(...)` before `DrawSkyBackground`. The color value is overdrawn immediately by the sky paint — the call is load-bearing for the DEPTH clear that comes with it on this raylib build. Without it, depth fragments from previous frames carry across and 3D props (trees especially) flicker / get hidden behind invisible depth-buffer holes that shift as the camera moves.
- Per-character XP / levels. Living party members earn the pack's `PackXPValue` on victory. Geometric cost curve: `XPForLevel(N) = LevelXPBase × LevelXPRatio^(N-1)` (100, 200, 400, …). Each level grants `LevelStatPoints` stat points (spent in the level-up modal — VIT spends auto-raise MaxHP and heal the difference) PLUS `LevelSkillPoints` skill points (saved on the member, spent later via the Skills panel's tier-purchase UI). Unspent points surface as a "+" badge on the party card name via `core.HasUnspentPoints`. The level-up modal is opened on demand from the panels overlay's Character / Stats tab — it no longer auto-fires post-battle.
- Party classes are intentionally named by class only: `Warrior`, `Cleric`, `Thief`, `Wizard`.
- Current class skills:
  - Warrior: `Swipe`, AoE damage.
  - Cleric: `Prayer`, party-targeted single heal.
  - Thief: `Steal`, flat base 40% chance scaled by timing quality only (no longer DEX-scaled). Rats carry `Morsel of Cheese`; bats carry `Bat Jerky`.
  - Wizard: `Firebolt`, single-target damage with a 45% base burn chance for 2-3 turns. Burns do not stack on an already-burning target.

## Implementation Notes

- Keep behavior repo-native and procedural unless asked otherwise. Most visual assets are generated in `textures.go`; the exception is authored enemy-billboard PNGs under `maps/sprites/` (procedural fallback retained).
- On-disk assets — `maps/*.map`, `maps/sounds/*.wav` (user cue overrides), `maps/sprites/*.png` — all resolve through `core.ResolveAssetDir(rel)`: cwd-relative first (so launching from the repo root works), then beside the executable (portable copy). Add new asset folders through that helper, never raw paths.
- **Billboard grounding gotcha.** Enemy/party billboards are CENTER-anchored via `rl.DrawBillboardRec` — there is no global per-sprite vertical placement, and the two views use DIFFERENT base heights: the walking field uses `enemyBillboardY` (~0.68), battle lifts the formation to `battleFormationCenterY` (1.0) to screen-center it under the narrow FOV. How "planted" a sprite looks depends on where its art sits inside the texture's transparent padding plus four per-kind knobs on `enemyVisual` (set in `loadEnemyVisuals`, all defaulting to the procedural-sprite norm of 0): `size` (a taller value grows the sprite both up AND down from center), `yOffset` (shifts only the sprite — calibrated against the battle center, so `drawFieldPacks` adds `enemyFieldLift` back to keep it grounded in the field too), `shadowRadius` (>0 paints a soft contact disc, tile-anchored),, `markerYOffset` (nudges the selector pyramid, which otherwise anchors to the un-lowered formation position — needed when `yOffset` drops a sprite away from its cursor), and `tint` (a per-kind base color multiplied into the runtime tint via `tintMul`/`resolveTint` — darken/recolor a sprite; zero value = untinted White). These are eyeballed per kind, not derived; expect to tune them when swapping art.
- Package boundaries are real Go package boundaries now. Prefer adding behavior in the relevant directory over creating prefixed files in `internal/app`.
- Use the existing raylib drawing style and helper functions before introducing a new rendering abstraction.
- Keep HUD surfaces rounded and slightly translucent; preserve readable borders and text shadows.
- Use `setBattleMessage` for real combat log events. Use `setBattleStatus` for transient prompts like target selection.
- Enemy death uses `deathFade`; do not immediately remove dead enemies from battle visuals if the fade is still active.
- Target tooltip text is centered, with wound-state labels from `core.EnemyConditionFor`.
- Party stat cards are pinned near the screen bottom and horizontally follow the projected party sprite positions.

## Init-time Invariants

The codebase enforces several data-consistency contracts at package init via `panic()` — if you add a new tile / enemy / skill / grade and forget one of the parallel tables, the program won't start. Read this list before adding a new "kind" of anything:

- **Skill handlers**: every `PartyClassDefinition.Skill` must be `PlayerCastable` AND have an entry in `battle/actions.go`'s `skillActionHandlers`. Every `PlayerCastable` skill in `core.PlayerCastableSkills` must have a handler. Asserted in `battle/actions.go` init.
- **Tile labels**: every char in `core.PropTileChars` / `DecorTileChars` / `floorTileCharList` must have a row in `tileLabelTable`. Asserted in `core/map.go` init.
- **Minimap colors**: every char in `core.PropTileChars` must have an entry in `render/minimap.go`'s `minimapPropColors`. Every blocking floor (`core.BlockingFloorChars`) must have an explicit case in `minimapTileColor` distinct from the open-tile fallback. Asserted in `render/minimap.go` init.
- **Decor / Prop / Door models**: every char in `core.DecorTileChars` / `core.PropTileChars` must either have an entry in `decorModels` / `propModels` or in `render/resources.go`'s `inlineDecorHandlers` / `inlinePropHandlers` map (for the hand-tuned bush/mushroom/tree/etc. cases drawn directly in `world.go`). Door styles must have a non-empty `doorProps` slot. Asserted in `assertDecorCoverage` / `assertPropCoverage` / `assertDoorProps` at `NewResources` time.
- **Enemy gold / drops**: every `EnemyDefinition` must have non-negative, ordered `GoldMin <= GoldMax`, and every `Drops` entry must carry a `Chance` in `[0, 1]` naming a registered `ItemKind`. Asserted in `core/enemies.go` init alongside the proc-chance checks.
- **Enemy visuals**: every kind in `core.EnemyKinds` must have an `enemyVisuals` entry with a non-zero texture. Asserted at the end of `loadEnemyVisuals`.
- **Editor entity colors**: every kind in `core.EnemyKinds` must have an `entityBrushColors` entry. Asserted in `editor/editor.go` init.
- **Material registry**: every `core.MaterialSet` (count `core.MaterialCount`) must have one `materialDefs` row (name + indoor trait) — asserted in `core/areas.go` init — AND a loaded `worldMaterial` — asserted by `assertMaterialCoverage` in `render`'s `NewResources`. `MaterialName` / `MaterialOptions` / `MaterialIsIndoor` all read the single `materialDefs` registry, so a new material is one row, not a grep for `== MaterialDungeon`.
- **Stat table**: `core.statTable` — plus the parallel `statSetters` and `statDescriptions` tables — must each have length `core.StatCount`. All three are length-asserted in `core/party.go` init, so a new `Stat` needs a row in every one or startup panics. `core/party.go` init ALSO calls `StatPreviewLine` for every `Stat` (a fourth, switch-shaped table the length-checks can't cover), so a new stat missing a preview case panics at startup, not mid-game when a player stages it.
- **Equip-slot table**: `core.equipSlotInfo` is a `[EquipSlotCount]struct{Label; Type}` — the single source for `SlotIndexLabel` / `SlotIndexType` (was two parallel switches). Sized `[EquipSlotCount]` (missing slot = compile error) and init-asserted non-empty in `core/items.go`, so a new equip slot is one row that can't go un-labeled or `SlotNone`-typed (which would make it silently un-equippable).
- **Panel-tab footer hints**: `render.panelTabFooterHints` is a `[core.PanelTabCount]string` parallel to `panelTabDrawers`; every tab must have a non-empty hint (asserted in `render/panels.go` init) so a new tab can't silently inherit a generic control hint that omits its own controls.
- **Timing grade tables**: `core.timingGrades`, `render.qualityVisuals`, and `battle.gradeSounds` all carry length-checks against `core.TimingQualityCount`. Adding a new grade is a four-file edit (timing.go iota, config.go row, timing.go row, battle.go row) and any one missing panics.
- **Pack-edit hotkeys**: `editor.packAddHotkeys` is a `map[core.EnemyKind]int32` (keyed by kind, not slice position, so reordering `enemyDefinitions` can't reshuffle bindings). Every kind in `core.EnemyKinds()` must have a non-zero key, no two kinds may share one, and no key may be in `packModalReservedKeys` (the modal's nav / member-op / close controls — else one press fires two actions). All three asserted in `editor/input.go` init.
- **Chest-edit hotkeys**: every item in `core.AllItems()` must have a corresponding key in `editor.chestAddHotkeys` so the chest-edit modal can add it via keyboard. Asserted in `editor/input.go` init.
- **Mapfile schema width**: `customEnemyEncodeFormat`'s `%`-verb count must equal `customEnemyFieldCount`. Asserted in `core/mapfile/mapfile.go` init — protects against the encoder and decoder drifting on column count when a new stat ships.
- **Panel-tab drawers**: `render.panelTabDrawers` is a `[core.PanelTabCount]func(...)` array; adding a new tab forces a slot, and a missing slot is a compile error (not a silent no-op).
- **Rain-kind visuals**: every `core.RainKind` must have a non-zero `rainVisuals` row in `render/weather.go`. Asserted in that file's init (the `[core.RainKindCount]rainVisual` array sizes itself, but a new kind's row would default to zero — the assert catches it).

When in doubt, run the program once — the panics are descriptive and point at the missing wiring.
